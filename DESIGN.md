# Country Search — Design

## 1. Отмена устаревших запросов

Вся логика — в [`src/search-controller.ts`](src/search-controller.ts), без DOM.

- Контроллер хранит **один** текущий `AbortController`.
- На **каждое** изменение ввода (`update`) сначала вызывается `controller?.abort()`, и только потом ставится debounce на новый запрос. Поэтому устаревший запрос отменяется сразу, а не через 350 мс, когда debounce запустит следующий: за время ожидания старый ответ не успеет прилететь и отрисоваться под новым текстом.
- `searchCountries(query, signal)` ([`src/search-countries.ts`](src/search-countries.ts)) объединяет сигнал вызывающего и таймаут: `AbortSignal.any([signal, AbortSignal.timeout(ms)])`.
- Отменённый `fetch` отклоняет промис с `DOMException` `AbortError`; `classifyError` ([`src/classify-error.ts`](src/classify-error.ts)) отличает его от `TimeoutError`, `HttpError` и сетевой ошибки. `abort` молча игнорируется, остальные — состояние `error` с кнопкой «Retry».
- 404 — не ошибка: `searchCountries` возвращает `[]`, контроллер показывает состояние `empty`.

**Почему не флаг «актуален ли ответ».** Флаг лишь прячет результат, а запрос продолжает жить: тратит трафик, держит соединение (браузер ограничивает их число на хост), нагружает API. Кроме того, проверку флага нужно помнить в каждой ветке (`then`, `catch`, `finally`) — легко забыть и получить мигание ошибки от старого запроса. С `AbortController` устаревший промис просто отклоняется, в Network он помечен как `canceled`, а код обработки результата не знает о гонке вообще.

Тест [`tests/search-race.test.ts`](tests/search-race.test.ts): мок `fetch` реагирует на `signal` и отклоняет промис с `AbortError`; поздний запрос резолвится раньше раннего, проверяется, что ранний отменён сразу при вводе и в итоговом состоянии только результат последнего запроса.

## 2. Задержка debounce — 350 мс

`SEARCH_DELAY_MS = 350`. Интервал между нажатиями при обычном наборе — примерно 100–300 мс, поэтому 350 мс покрывает непрерывный ввод слова, и запрос уходит на паузе, а не на каждую букву. При этом задержка ниже порога ~400–500 мс, после которого интерфейс ощущается «тормозящим».

- **Без debounce** — запрос на каждую клавишу. Отмена спасает от гонки, но лишние запросы всё равно создаются и обрываются, мигает индикатор загрузки, растёт риск упереться в rate limit API.
- **Сильно больше (1–2 с)** — пользователь допечатал и ждёт, ничего не происходит; кажется, что поиск не работает.

## 3. Сложность (Big O)

| Функция                                               | Время                                                                                       | Память                                 |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------- | -------------------------------------- |
| `mapCountryResponse(raw)`                             | O(L + C + B) — языки, валюты, границы одной страны; на практике O(1), это единицы элементов | то же                                  |
| маппинг ответа в `searchCountries`                    | O(n · (L + C + B)) ≈ O(n), n — число стран в ответе                                         | O(n)                                   |
| кэш `createCachedSearch`: попадание / поиск in-flight | O(q) на `toLowerCase` ключа длины q + O(1) в среднем на `Map.get`                           | —                                      |
| подписка на in-flight запрос и её отмена              | O(1): счётчик подписчиков, `abort()` только когда он стал 0                                 | O(1) на вызов                          |
| кэш в целом                                           | —                                                                                           | O(K · n), K — число различных запросов |
| `addToHistory`                                        | O(h), h ≤ 8                                                                                 | O(h)                                   |

Дедупликация: одинаковые одновременные запросы делят один промис ([`src/cached-search.ts`](src/cached-search.ts)), но каждый вызывающий получает свой промис со своим `signal`. Отмена одним вызывающим отклоняет только его промис; общий запрос обрывается, лишь когда отменились все. Ошибки не кэшируются.

## 4. Принципы чистого кода

- **Single Responsibility** — один модуль, одна задача: HTTP — `search-countries.ts`, маппинг — `map-country-response.ts`, классификация ошибок — `classify-error.ts`, состояние поиска — `search-controller.ts`, отрисовка — `view.ts`/`details.ts`, сборка — `main.ts`.
- **Чистые функции** — `mapCountryResponse`, `classifyError`, `addToHistory`, функции в `format.ts`: без побочных эффектов, тестируются на JSON-фикстурах без сети.
- **Dependency Injection** — `createSearchController(search, onChange)` получает функцию поиска и колбэк рендера; `loadHistory/saveHistory(storage)` получают хранилище. Поэтому логика тестируется без браузера.
- **Open/Closed, декоратор** — `createCachedSearch(search)` оборачивает любую `Search` с той же сигнатурой; контроллер не менялся при добавлении кэша.
- **DRY** — `el()` и `infoList()` в `dom.ts` используются карточкой и детальным видом; `flag()` общий; `update()` в контроллере объединяет `input`/`search`/`retry`; `mockFetch()` переиспользуется в тестах.
- **KISS** — без фреймворков и библиотек; состояние — размеченное объединение `SearchState`, рендер — один `switch` в `renderState`.
- **Никаких магических чисел** — `SEARCH_DELAY_MS`, `REQUEST_TIMEOUT_MS`, `NOT_FOUND`, `HISTORY_LIMIT`, `ERROR_MESSAGES`.
- **Безопасный DOM** — только `createElement`/`textContent`, никакого `innerHTML`.
